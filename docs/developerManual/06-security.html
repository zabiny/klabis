Bezpečnost

Klabis je OAuth2 Authorization Server i Resource Server v jedné aplikaci. Frontend získává access token přes Authorization Code Grant + PKCE. Autorizace má tři vrstvy: endpoint-level (SecurityConfiguration), method-level (@HasAuthority + @TargetId) a field-level (@OwnerVisible, @ReadAuthority). Method- i field-level rozhodnutí dělá jediný AuthorizationEvaluator nad snapshotem oprávnění, který se načítá pro každý request.

Přehled bezpečnostní vrstvy

HTTP request flow

Když browser žádá URL na backendu, request prochází několika vrstvami v tomto pořadí:

  1. Spring Security filter chains (řazené podle @Order) — autorizační server matcher (@Order(1)), /login form chain (@Order(2)), /docs/** session-auth chain (@Order(3)), /h2-console/** chain (@Order(2), dev only), SPA text/html chain (@Order(4)), API + actuator + Swagger chain (@Order(5)). První, jehož securityMatcher sedí, request zpracuje; ostatní jsou přeskočeny.
  2. DispatcherServlet mapuje request na @Controller / @RequestMapping handler. Pokud najde, zavolá ho.
  3. ResourceHttpRequestHandler (přes WelcomePageHandlerMapping) hledá soubor v classpath:/static/. /index.html, /assets/**, /docs/index.html, /swagger-ui/index.html, /silent-renew.html, ikony — všechno odsud.
  4. SpaFallbackFilter (OncePerRequestFilter, LOWEST_PRECEDENCE) — teprve když všechny předchozí kroky selhaly:
    • Pokud request je GET, klient akceptuje text/html a cesta není na vyloučeném prefixu (/api/, /swagger-ui/, /v3/api-docs, /docs/, /oauth2/, /.well-known/, /actuator/, /h2-console/, /error) → forward na /index.html (SPA shell).
    • Jinak request projde dál a klient dostane standardní 404 (JSON pro API klienty, HTML error page jinak).
    Filtr rozhoduje předem: kontroluje resourceLoader.getResource("classpath:/static" + path).exists() a pokud soubor existuje, jen propustí request dál — žádné wrappování response.
Rule of thumb: SPA shell (/index.html) se vrací pouze když žádný předchozí handler request neobsloužil. Cokoli s vyhrazeným handlerem (Swagger UI, OpenAPI, dev manuál, OAuth2 endpointy, silent-renew, statické assety, API) nikdy nedostane SPA shell.
PWA service worker: ve frontendu (vite.config.ts) je nakonfigurovaný Workbox service worker s NavigationRoute, který v běžícím prohlížeči zachytává navigační requesty na SPA scope a vrací cached /index.html. Jeho navigateFallbackDenylist musí pokrývat stejné prefixy jako SpaFallbackFilter.EXCLUDED_PREFIXES + EXCLUDED_EXACT, jinak SW přepíše backend i pro URL, které backend obsluhuje (Swagger UI, dev manuál apod.).

JWT a vlastní claims

Access token uživatele vydávaný Klabisem nese kromě standardních claims (sub, aud, iat, exp) i:

  • user_id — UUID interního Useru (nikoli registračního čísla).
  • memberIdUuid — UUID členského profilu (chybí u admin účtů bez Member profilu).
  • registrationNumber — používá se pro audit (createdBy/lastModifiedBy).

Uživatelský token nenese claim authorities — oprávnění se čtou z databáze pro každý request (viz Snapshot oprávnění), takže udělení i odebrání oprávnění platí od dalšího requestu bez nového přihlášení. Výjimkou jsou client_credentials tokeny (bez user_id): ty dál nesou authorities odvozené ze scopes (AuthorizationServerConfiguration.SCOPE_TO_AUTHORITIES).

Konstanty názvů jsou v KlabisOAuth2ClaimNames. Jejich přidání do tokenu zajišťuje KlabisAuthorizationServerCustomizer (viz sekce "OAuth2 přizpůsobení" níže na této stránce).

KlabisJwtAuthenticationToken

public class KlabisJwtAuthenticationToken extends JwtAuthenticationToken {
    public AuthorizationSnapshot snapshot();                // líně načtený, memoizovaný (jednou na token = jednou na request)
    public Collection<GrantedAuthority> getAuthorities();   // overAll ze snapshotu
    public UserId getUserId();
    public Optional<UUID> getMemberIdUuid();
    public boolean hasMemberProfile();
    public boolean isSelf(UUID id);                         // id uživatele nebo člena — používá jen evaluator
    public String getUsername();
}

Resource server vyrobí nový token pro každý request. KlabisJwtAuthenticationConverter mu předá supplier snapshotu (volá AuthorizationSnapshotLoader), který token zmemoizuje: první autorizační otázka requestu snapshot načte, všechny další ho čtou. getAuthorities() vrací oprávnění „nad vším“ z tohoto snapshotu, takže Spring hasAuthority(...) SpEL na metodě vidí stejná oprávnění nad vším jako evaluator (granty nad konkrétními cíli ale nevidí — pro ty používejte @HasAuthority + @TargetId). Bez přihlášeného uživatele (listenery, scheduled joby) je snapshot prázdný a nic se neautorizuje.

Pokud potřebujete v controlleru aktuálního uživatele, nepoužívejte přímo SecurityContextHolder. Použijte parametrové anotace @ActingUser / @ActingMember z modulu members (kap. 05). CurrentUserData nese jen identitu (userId, memberId) — na oprávnění se ptejte AuthorizationEvaluatoru.

Authority enum

Type-safe seznam všech autorit (com.klabis.common.users). Každá autorita deklaruje, čeho se týká (targetType) a v jaké formě ji lze držet (grantForms). 

public enum Authority {
    CALENDAR_MANAGE("CALENDAR:MANAGE", TargetType.NONE, GrantForm.ALL),
    MEMBERS_MANAGE("MEMBERS:MANAGE", TargetType.MEMBER, GrantForm.ALL),
    MEMBERS_READ("MEMBERS:READ", TargetType.MEMBER, GrantForm.ALL),
    MEMBERS_PERMISSIONS("MEMBERS:PERMISSIONS", TargetType.MEMBER, GrantForm.ALL),
    EVENTS_READ("EVENTS:READ", TargetType.EVENT, GrantForm.ALL),
    EVENTS_MANAGE("EVENTS:MANAGE", TargetType.EVENT, GrantForm.ALL),
    EVENTS_REGISTRATIONS("EVENTS:REGISTRATIONS", TargetType.MEMBER, GrantForm.ALL),
    GROUPS_TRAINING("GROUPS:TRAINING", TargetType.NONE, GrantForm.ALL),
    FINANCE_MANAGE("FINANCE:MANAGE", TargetType.NONE, GrantForm.ALL),
    SYNC_MANAGE("SYNC:MANAGE", TargetType.NONE, GrantForm.ALL),
    DEVELOPER("DEVELOPER", TargetType.NONE, GrantForm.ALL);

    public String getValue();                       // "MEMBERS:MANAGE"
    public TargetType getTargetType();
    public Set<GrantForm> getGrantForms();
    public static Set<Authority> assignableAuthorities();
    public static Set<Authority> delegatable();
    public static boolean isKnownAuthority(String value);
}
TargetType (MEMBER, EVENT, NONE)
Druh cíle, kterého se autorita týká. NONE = autorita nesouvisí s konkrétním objektem.
GrantForm.ALL
Autoritu lze držet nad vším daného typu (včetně později vytvořených cílů) — to je dřívější „globální“ oprávnění. Jen tyto autority nabízí dialog oprávnění (assignableAuthorities(), bez standardních autorit a DEVELOPER).
GrantForm.SPECIFIC
Autoritu lze držet nad konkrétními cíli, odvozenými ze vztahu (delegatable()). Autorita jen s {ALL} je administrátorská a delegovat ji nelze. Zatím ji nemá žádná autorita.
isKnownAuthority(value)
Použije se k filtrování — Spring DaoAuthenticationProvider přidává FACTOR_PASSWORD autoritu, kterou nechceme mezi oprávněními.

Snapshot oprávnění a AuthorizationEvaluator

Balíček com.klabis.common.authorization (named interface authorization) obsahuje jediný model oprávnění. Rozhodnutí a důvody viz ADR-010 v docs/design-decisions.md. 

public final class AuthorizationSnapshot {
    public Set<Authority> overAll();
    public boolean hasOverAll(Authority authority);
    public boolean has(Authority authority, TargetRef target);   // overAll ∨ target ∈ overTargets
    public Set<TargetRef> targetsOf(Authority authority);
}

public interface RelationshipSource {                            // SPI pro moduly
    Map<Authority, Set<TargetRef>> grantsOf(UserId userId);
}

public record TargetRef(TargetType type, UUID id) { ... }
overAll
Oprávnění nad vším — z PermissionService (řádek user_permissions) plus standardní autority.
overTargets
Sjednocení grantů všech RelationshipSource beanů. Přijmou se jen autority s SPECIFIC a odpovídajícím targetType — zdroj nemůže rozdat administrátorskou autoritu. Implementace patří do infrastructure vlastnícího modulu a čte jen jeho repository (ADR-001). Zatím žádná neexistuje.
AuthorizationSnapshotLoader
Načte snapshot uživatele (PermissionService + všechny RelationshipSource, 1 + N(zdrojů) dotazů). Volá ho jen token, a to nejvýše jednou na request; requesty bez autorizační otázky neplatí nic.
AuthorizationSnapshotProvider
current() vrací snapshot aktuální autentizace: u uživatelského tokenu ten, který token nese (všechna rozhodnutí v jednom requestu tak vidí jednu sadu oprávnění), u client_credentials snapshot z autorit tokenu bez cílových grantů, bez autentizace prázdný.

AuthorizationEvaluator je jediné místo, které na oprávnění odpovídá:

MetodaKdo ji používá
canInvoke(method, targetClass, args)HasAuthorityMethodInterceptor, HalFormsSupport (affordance, klabisLinkTo)
canReadField(accessor, record)SecuredBeanPropertyWriter (pole response)
canWriteField(accessor, target), canReadRequestField(...)RequestBodyFieldAuthorizationAdvice, HAL-FORMS readOnly / skrytí property
has(authority), has(authority, target), isSelf(target)aplikační kód — controllery, postprocessory

Pravidlo pro prvek chráněný autoritami [A1..An], volitelným cílem t a @OwnerVisible:

allowed ⇔ ∃ Ai: (t ? has(Ai, t) : hasOverAll(Ai))  ∨  (ownerVisible ∧ isSelf(t))

Protože vynucení i nabízené akce jdou stejnou cestou, je nabídnutý HAL-FORMS template nebo link vždy akce, kterou uživatel smí provést.

ArchUnit test AuthorizationArchitectureTest shodí build, pokud kód mimo common.authorization a common.security čte @HasAuthority, @OwnerVisible, @TargetId, @ReadAuthority nebo Authentication.getAuthorities(). Imperativní kontrolu v controlleru napište jako authorizationEvaluator.has(Authority.MEMBERS_MANAGE, TargetRef.member(id)).

Method-level autorizace: @HasAuthority a @TargetId

@Target({ElementType.TYPE, ElementType.METHOD})
public @interface HasAuthority {
    Authority[] value();          // stačí kterákoli z nich
}

@Target({ElementType.PARAMETER, ElementType.RECORD_COMPONENT, ElementType.METHOD})
public @interface TargetId {      // com.klabis.common.authorization
    TargetType value();
}

Anotace se negenerují ručně — vznikají ze spec extensions x-klabis-authority (hodnota nebo seznam), x-klabis-owner-visible a x-klabis-target-id: MEMBER na generovaném *Api rozhraní (kap. 05). Výsledný tvar: 

public interface MembersApi {

    @HasAuthority({ Authority.MEMBERS_MANAGE })
    @OwnerVisible
    ResponseEntity<Void> updateMember(
            @TargetId(TargetType.MEMBER) @PathVariable("id") UUID id,
            @RequestBody UpdateMemberRequest request);
}
Bez parametru @TargetId musí být autorita držena nad vším; s ním stačí i nad tímto cílem. @OwnerVisible přidává OR „cíl jsem já“; samotné znamená owner-only. @OwnerVisible bez @TargetId odmítá — validátor specu to nepustí.

Field-level autorizace

Pole DTO se filtrují podle autorizace při serializaci. Anotace lze kombinovat (OR semantika). Field bez oprávnění se buď vynechá z odpovědi, nebo nahradí maskovanou hodnotou (záleží na @HandleAuthorizationDenied handleru). 

public record MemberDetailsResponse(
        @TargetId(TargetType.MEMBER) UUID id,
        String firstName,
        @HasAuthority({ Authority.MEMBERS_MANAGE }) @OwnerVisible
        String email,
        @HasAuthority({ Authority.MEMBERS_MANAGE }) @OwnerVisible
        String birthNumber
) {}
@TargetId
Komponenta recordu (nebo parametr), která identifikuje cíl. Bez ní se pro @OwnerVisible pole použije jediná komponenta konvertibilní na UUID (bere se jako člen). Komponenta s kolekcí id je množina vlastníků: autority pak musí být drženy nad vším.
@OwnerVisible
Pole je viditelné, když je cílem sám přihlášený člen (isSelf).
@ReadAuthority
Jen na request DTO (x-klabis-read-authority): uživatel s touto autoritou, který pole nesmí měnit, ho v HAL-FORMS template vidí jako readOnly místo skrytí.
Request DTO (PATCH)
JsonNullable pole s anotacemi kontroluje RequestBodyFieldAuthorizationAdvice přes canWriteField; cíl čte z @TargetId @PathVariable handleru. Nepovolené přítomné pole → 403.

isSelf

AuthorizationEvaluator.isSelf(target) porovná členský cíl s id uživatele a s memberIdUuid z KlabisJwtAuthenticationToken (token.isSelf(id)). Hodnoty cílů (např. MemberId) se na UUID převádějí přes Spring ConversionService — proto modul members registruje MemberIdToUuidConverter.

Pravidla polí se vyjadřují jen anotacemi @HasAuthority, @OwnerVisible, @TargetId a @ReadAuthority; SpEL @PreAuthorize na polích se nepodporuje (na metodách dál funguje přes getAuthorities()).

OAuth2 přizpůsobení v modulu members

Modul members rozšiřuje sdílený OAuth2 stack o bridging specifický pro Klabis mezi User aggregate a Spring Security. Tyto třídy jsou framework-úrovňové, ne byznys logika.

KlabisAuthorizationServerCustomizer
Implementace AuthorizationServerCustomizer SPI z common.security. Zapojuje token claims specifické pro Klabis (registrationNumber, memberIdUuid, firstName, lastName — bez authorities) do AS chainu během vydávání tokenu. Auto-registruje se jako @Component.
KlabisUserDetailsService
Bridge: načte User + UserPermissions a vrátí Spring Security UserDetails. Klíčové pro DaoAuthenticationProvider při login flow. Poskytuje i metodu loadKlabisUserDetails(userName) pro přístup z aplikačního kódu nezávislý na Spring Security.
MemberIdToUuidConverter
Spring Converter<MemberId, UUID> registrovaný do ConversionService. Vyžadovaný pro field-level autorizaci — AuthorizationEvaluator potřebuje generic konverzi @TargetId hodnoty na UUID, aby ji mohl porovnat s identitou uživatele z JWT.
